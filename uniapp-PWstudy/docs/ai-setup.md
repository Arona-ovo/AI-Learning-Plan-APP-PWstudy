# 填 API：为什么、在哪、怎么验（2026-11-01）

> 用户口径：「引导做得更好一些，并且要提示用户填 API，不然大部分无法使用。」

## 一、问题不是"引导不好看"，是没人知道有这件事

PWstudy 的主体功能全走**用户自己的大模型账号**：

| 功能 | 没有 API 时 |
|---|---|
| AI 规划（定目标 → 拆日程） | 只能走本地兜底排期（`localPlan`），没有追问、没有资料/工具建议 |
| 收工对话（"说一句今天的出入"） | 完全不可用 |
| 学习 App 识别（`ai-app-guess`） | 只能靠包名 + 图标猜，猜不出就空着 |
| 云端朗读（`/audio/speech`） | 回退本地 TTS |

而配它的路径原本是：`我的 → 设置 → AI 服务 →（打开默认关着的总开关）→ 连接参数 → 展开 → 四个输入框`。
四层折叠、一个默认关闭的开关 —— 新用户在里面迷路的概率远高于配完的概率，
表现出来的却是"这 App 一半功能是坏的"。

## 二、这次做了什么

### 1. 专用页 `pkgManage/pages/ai-setup/ai-setup.vue`

压成三步：**选服务商 → 粘 Key → 测试并保存**。

- 服务商预设（`PROVIDER_PRESETS`）带好地址与模型，绝大多数人只需要粘一个 Key
- 「从剪贴板粘贴」：手机上长按输入框选"粘贴"很容易点错，复制场景又多来自电脑
- 「去申请一个」按服务商给控制台地址（OpenAI / DeepSeek / Kimi / 通义百炼），
  开不了浏览器就把地址丢进剪贴板
- 地址与模型折叠着（默认值已填好），点开可改；选「自定义」时自动展开
- 保存时**同时置 `enabled: true`** —— 这是最隐蔽的一处：只存 key 不置总开关，
  测试通过了、功能全都不动，因为 `isAIEnabled()` 还看到 false
- **先落盘再测**：`testAIConnection()` 读的是 settings，顺序反了测的是上一份配置
- 测失败把原因原样摊在页面上（"连接失败"四个字帮不上忙），成功停 700ms 再返回

复用而不是重写：`PROVIDER_PRESETS` / `chatEndpoint` / `validateKeyFormat` /
`testAIConnection` 全来自 `services/`，与设置页同一套判定 —— 免得"这边说可用、那边说不通"。

### 2. 三个提醒入口（没配的时候）

| 位置 | 形态 | 逻辑 |
|---|---|---|
| 首页 | 临时卡「还差一个 API Key」 | 与权限卡同皮肤，点 × 只记 `ai.promptMuted`（"别催了"）；配好自动消失 |
| 开始前的几件事 | 顶部的 AI 卡（在权限清单之前） | 首次启动必经那一屏；有状态点 + 「去填写」按钮 |
| 规划页 | 原来那行死文字 → 可点的提示条 | 点一下直达填写页，回来 `onShow` 立刻重算 `aiReady` |

三处都走 `services/config.js` 的 `aiGateReason()`，页面里不另拼条件
（判定只许有一个出处，否则迟早出现"首页说没配、设置页说已配"）。

### 3. 引导：末步换成「填 API」（`VERSION` 1 → 2）

步骤表从 5 步重排：欢迎 → 开始专注 → 今日任务 → 今日收工 → **填 API**。

- 底部导航那步撤掉（三个 tab 都写着字，信息量最低），腾给填 API
- 末步带**行动按钮**：「现在去填」+「以后再说」。遮罩通过 `@action` 抛事件，
  首页 `guideAction()` 先 `endGuide()`（记完成、收遮罩）再跳 —— 不收起就跳页，
  回来会看到一层停在不适用步骤上的遮罩
- 步骤表支持 `when(opts)` 在场条件：**已经配好 AI 的人看不到这一步**（别教老手填密钥）
- `opts` 由首页 `guideOpts()` 给，值是**开场那一刻的快照**（`gdAiReady`）：
  用户从引导里点「现在去填」、填完回来时步骤表长度若变了，`gdIndex` 会直接错位
- `isDone()` 现在要求 `ob.v >= VERSION`：步骤表换了（这次把末步换掉），
  老用户也重看一遍。只判 `done` 的话，改版后所有人都停在旧的"看过了"上，新那步永远没人看见

## 三、验证

```
① 全新安装 → 走完「开始前的几件事」→ 顶部 AI 卡应显示「还没填」+「去填写」
   点进去 → 选服务商（地址/模型已预填）→ 粘 Key → 测试并保存
   成功：绿色「测试通过」→ 自动返回 → 那张卡变成「已开启」
② 首页（没配的状态）→ 临时卡「还差一个 API Key」在最上面
   → 点它进填写页；配好后返回，卡应自己消失
   → 点 × 则记静音，本轮不再出现（设置里仍有入口）
③ 引导：故意清掉 `settings.onboarding`（或设置页「重看引导」）
   → 末步应出现「现在去填 / 以后再说」两个按钮
   → 点「现在去填」应直接进填写页，且回来不再重复弹引导
   → 已经是可用配置时，末步**不该出现**（只有 4 步）
④ 规划页：没配 AI 时那条橙色提示可以点，点了直达填写页，配好回来提示消失
⑤ 反例（必须仍然报错而不是静默降级）：填一个错的 Key → 应显示服务端返回的
   401/权限错误原文，而不是白屏或"成功"
```

护栏：`node _tools/check-ai-setup.js`（新增，接在 `run-all` 里自动跑），
反向 `_tools/_scratch/neg-onboarding.js` 第 19/20 条专盯这次加的行动按钮。

## 四、已知限制

- 只支持 **OpenAI 兼容**接口（`/chat/completions`）。Anthropic / Gemini 原生协议不认，
  得走中转 —— 页面上那句"用的是 OpenAI 兼容接口"就是为这个准备的
- 云端朗读额外要 `/audio/speech`，多数国产服务没有，会自动回退本地 TTS
  （设置页的「地址支持语音」开关只对自定义地址生效）
- 密钥明文存在本机 storage（`settings.ai.apiKey`）。这是"用户自带 key"的必然结果：
  我们没有服务端，也就不可能代管。页面上写明了"只存在这台手机上"
