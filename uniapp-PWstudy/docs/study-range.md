# 学习范围（在 / 不在学习地点）

> 「圈出你常学习的地方，人不在的时候系统知道，拿去喂 AI 让它排得更懂事。」

## 它是干什么的

用户圈几个学习地点（家 / 图书馆 / 自习室，各自带一个半径）。App 在几个固定时刻
取一次定位，记下"这会儿在不在范围内"。

这批数据只有一个用途：**告诉 AI 那几段人客观不在场**，于是 ——

- 排任务时绕开这些时段（不把活儿排到一个注定没人的下午）；
- 总结时不把"没做完"算成偷懒或能力下降。

它**不**做这些事：不实时追踪、不弹窗提醒、不暂停专注、不通知。
判定"出去了"之后什么都不发生，只是一条事实记录。

## 三条边界（改这块前先读）

### ① 经纬度即用即弃，绝不落库、绝不上网

| 位置 | 存什么 |
|---|---|
| `settings.range.places[]` | 用户亲手填的地点（含 lat/lng）—— **只存在于设置里** |
| `pwstore.daily[key].range[]` | 只有 `{ at, inside }` 两个字段，**没有坐标** |
| AI 上下文（`harvest.rangeBlock`） | 只有时段与分钟数，**连地点名都没有** |

坐标在 `location.checkNow()` 里交给 `insideAt()` 算完距离就丢弃了，
返回的只有布尔。这条红线由 `check-range.js` 第 3 节守着。

### ② 不做后台持续定位

取一次定位要唤醒 GPS / 网络定位，是耗电动作。后台持续定位还要额外申请
`ACCESS_BACKGROUND_LOCATION` —— 应用商店重点审查的权限，国产 ROM 上还各有各的
限制（有的根本不给）。而我们要的只是"哪几段人不在"，不是轨迹。

所以只在三个时机取样，且**至少隔 5 分钟**：

| 时机 | 位置 | 是否 force |
|---|---|---|
| 打开 App / 从后台切回前台 | `App.vue` `onShow` | 否（走节流） |
| 专注开始 | `utils/focus.js` `startFocus` | 是 |
| 专注结束 | `utils/focus.js` `finishFocus` | 是 |
| 设置页手动点「刷新」 | `pkgPlan/pages/range/range.vue` | 是 |

开始 / 结束强制取样，是因为那才是"人到底在不在"最该记的时刻：
开始在场、结束在场，中间那一段才算真的"人在"。只记开始不记结束，
"专注中途出去了"这条信息永远攒不出来。

采样稀疏是**设计**，不是精度缺陷。

### ③ 关着的开关不申请权限、不取样

`settings.range.on` 默认 `false`。关着的时候 `checkNow()` 第一行就返回，
一个权限都不会申请，一次定位都不取。

同样地，权限引导那条横幅只在 `on && !granted` 时才出现 ——
没开这个功能的人不该被要求授权。

## 数据结构

```
daily['2026-10-23'].range = [
  { at: 08:00, inside: true  },
  { at: 12:00, inside: false },   ← 走了
  { at: 13:30, inside: true  }    ← 回来了
]
```

**只记状态翻转**：在家坐一下午只会有 1 条记录，不会攒成心跳日志。

摘要 `pwstore.rangeSummary(key, days)`（签名与风格照抄 `extStudySummary`）：

| 字段 | 含义 |
|---|---|
| `times` | 不在范围内有几段 |
| `outMin` | 合计分钟 |
| `outDays` | 涉及几天 |
| `avgMin` | 平均每段多久 |
| `topHours` / `byHour` | 出去得最多的时段 |
| `spans[]` | 每段的 `{date, from, to, min}` |
| `openEnds` | 有几天"最后一次看到他时还在外面、之后没消息" |

### 时长只认能确定首尾的那几段

第一次采样就已经在外面（不知道什么时候走的）、或者那天之后再没消息
（不知道什么时候回来的）—— 这两段时长**不可知，一律不计**。
宁可少报，也不能拿一个拼出来的时长去让 AI 少排任务。

唯一的例外是今天：如果最后一次采样还是"在外面"，可以补"到现在"
（人就在此刻不在场，这是事实），这段标记 `open: true`。

## 喂给 AI 的样子

`harvest.rangeBlock()` 拼出这样一块，跟在 `externalBlock()` 后面进 `extra`：

```
【在 / 不在学习范围（近 7 天，本人设定的学习地点）】
- 不在范围内共 3 段 · 合计 5 小时 20 分 · 平均每段 106 分钟 · 涉及 2 天
- 出去得最多的时段：12 点（210 分钟）、18 点（110 分钟）
- 最近几段不在范围内：
  · 2026-10-23 12:00-13:30 · 1 小时 30 分
  · 2026-10-22 17:40-19:00 · 1 小时 20 分
- **这些时段他客观不在学习地点，做不了事，不是偷懒也不是能力下降**：
  不要据此下调对他的判断，不要在反馈里说"投入不足"之类的话。
- 排期上：这些时段不要安排任务；若正好撞上，用 move 挪开而不是 drop 砍掉。
  已经落下的量按"人不在"处理，往后匀即可，不要压缩他一天该做的总量。
```

### ⚠️ 那句"不是偷懒"不能删

不给这句话，模型看到"下午 3 小时不在"最常见的反应就是砍任务量
（drop / resize 减量），或者在总结里说一句"近期投入不足"。
那是把客观不在场误判成主观懈怠 —— 用户看到那句话会觉得这 App 在指责自己，
这功能的初衷就反了。`check-range.js` 专门守着这一句。

同样的口径也要进 `coach.context()`：不然用户说"今天下午啥也没干"，
模型不知道他下午人根本不在家，很容易接一句"要不要把任务量调小一点"。

## 入口与开关

- **我的 › 学习范围**（`pkgPlan/pages/range/range.vue`）
- 总开关在页面第一张卡；关着不申请权限
- 加地点：点「＋ 加地点」→ 取到当前 GPS 后开**真地图**（高德底图）→ 点地图 / 拖图钉定位置、拖滑块 / 快捷档定半径 → 起个名
- 微调已有地点：点地点行的「半径 米 ›」→ 进小地图改位置与半径
- 半径：自由连续 30–5000 米（滑块）+ 100 / 200 / 500 / 1000 米四档快捷
- **归中（2026-10-26 补）**：
  - 地图右下角「定位」cover-view 钮：取一次当前 GPS，图钉 + 视野一起归中到当前位置；
    失败按错误码说人话（没权限 / 定位服务没开 / 定位失败）。原生地图层级最高，
    地图内的浮动控件只能用 `cover-view`（普通 view 盖不住，这是 app-vue 的硬规矩）；
  - 编辑模式下图钉挪离了地点原坐标 → 读数行出现「回到原位」（撤销手滑）；
  - 视野回图钉统一走 `centerMap()` → `moveToLocation({lat, lng})`（App 2.6.8+ 支持
    传坐标）：「原地再定位」与「拖走地图再点回来」两种场景 latitude/longitude prop
    看不出变化，光靠 prop 拉不回视野；
  - `<map>` 同时开了 `show-location`（蓝点标出"我在哪"；平台不支持时自动忽略，无害）。
- 图钉素材：`static/pin.png`（`_tools/gen-pin.py` 生成，绯红水滴 + 白描边）。
  **必须存在** —— marker 的 `iconPath` 是必填项，文件缺失时高德取不到 bitmap，
  图钉整个不画（2026-10-26 前一直缺这张图，用户看到"地图上一个点都没有"）。

## 打包相关

⚠️ 这个功能动到了原生配置：

- `manifest.json` 的 `distribute.android.permissions` 加了
  `ACCESS_COARSE_LOCATION` / `ACCESS_FINE_LOCATION`；
- `app-plus.modules` 勾了 `Geolocation`（不勾的话云打包出来 `uni.getLocation`
  会报模块未配置）；
- `distribute.sdkConfigs.maps.amap` 配了高德 key（android 必填，ios 占位即可，
  **不填真 key 地图会加载失败**）。

所以它**必须跟着一次云打包 APK 发**，wgt 装不进去（地图 SDK 是原生模块，wgt 包不住）。

## 已知取舍 / 没做的

- **本地兜底 `harvest.localRoll()` 用不上这份数据**：它只算 `goal` 对象，
  一行 daily 都不读。要让"人不在"也影响本地铺开，得改它的 `span` 计算 ——
  那是另一笔改动，先不做。
- **不加"出去时提醒"**：判定出去后不做任何打扰。等有人真提出想要再说。
