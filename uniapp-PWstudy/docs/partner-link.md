# PWstudy ↔ AWword 联动设计

> 面向两个仍在持续演进的 App。本文既是实现依据，也是给「背单词 App 侧」的交接说明
> （第 11 节可直接转给负责 AWword 的同学 / AI）。

---

## 0. 一句话定位

**PWstudy 管「你打算学多久」，AWword 管「你实际学会了什么」。关联只是让这两件事能对上号。**

不关联，两个 App 各自都完整可用；关联，只是少一次手动切换、多一路真实数据。

---

## 1. 设计原则（先立规矩，后面所有取舍都回到这里）

| # | 原则 | 具体含义 |
|---|---|---|
| 1 | **绝不独占** | PWstudy 是「学习 App 之一」，不是「唯一背单词入口」。dock 里登记的第三方背单词 App 一如既往可用，关联 AWword 不会挤掉它们，也不会改它们的统计口径 |
| 2 | **可跳过** | 首次提示必须能「以后再说」和「不用了」，且「以后再说」不会无限骚扰（最多 3 次） |
| 3 | **可关闭** | 设置页常驻入口，已关联的随时能取消；取消后不再有任何跳转、提示、横幅 |
| 4 | **不影响主流程** | 未安装 / 未关联 / 已取消，三种状态下 PWstudy 的功能**一条不少**，番茄钟、强制模式、重排、统计全部照常 |
| 5 | **数据是单向增量** | 关联只做「累加事实」，不做「覆盖真相」。对方回传什么就记什么，不反推、不改写本地已有记录 |

---

## 2. 术语

- **伙伴 App（partner）**：与本 App 建立关联的那个 App。当前只有 AWword，注册表设计上支持多个（第 10 节）。
- **关联（link）**：一种**本地意愿记录**——"我愿意在两者之间跳转并交换数据"。它不是一个账号、不是云端状态。
- **会话（session）**：一次「从 PWstudy 跳过去 → 在 AWword 学 → 跳回来」的完整往返。
- **战果（payload）**：回来时携带的数据（时长 / 词数 / 任务 id）。

---

## 3. 技术边界（先说清楚能做什么，避免期待落差）

**这三个是硬事实，决定了整套设计的形状：**

1. **两个 APK 的本地存储互相看不见。** Android 沙箱隔离，PWstudy 读不到 AWword 的 Storage，反之亦然。
   → 所以**不存在"共享一个学习进度数据库"这回事**。
2. **URL 参数容量有限。** 跳转能带的数据量只够放十来个字段，塞不下词书内容、错题本、历史曲线。
3. **Android 11+ 有包可见性限制。** `targetSdk < 30` 的应用默认能看到所有已安装包；
   `targetSdk >= 30` 的应用必须在 manifest 里声明 `<queries>` 才能检测到对方。
   PWstudy 目前 `targetSdk = 28`（不受限），但 AWword 侧若已升到 30+，需要显式声明（见 11.2）。

**因此"同步"在本文里的准确定义是：**

> **会话式同步** —— 每次跳转往返时，双方各带一份**状态快照**过去/回来。
> 不是实时双向同步，也不是云端同步。

这不是妥协，而是这两个 App 都是**纯本地、无账号、无后端**——它们本来就没有"云上那份真相"可同步。
好处也在这里：不存在多端冲突、不存在账号体系、不需要登录。

## 4. 关联状态机

每个伙伴 App 在本地存一份状态，四个状态：

```
                    ┌──────────────────────────────┐
                    │                              │
   (首次检测)        ▼                              │
   ┌─────────┐  关联  ┌─────────┐  取消关联  ┌─────────┐
   │  未决定  │──────▶│  已关联  │──────────▶│  已关闭  │
   │ (undec) │       │(linked) │           │(declined)│
   └─────────┘       └─────────┘            └─────────┘
        │  "以后再说"        ▲                     │
        │  (askedCount+1)   │      重新关联        │
        └───────────────────┴─────────────────────-┘
                    设置页可随时回到「已关联」
```

字段定义（`settings.partner`）：

```js
partner: {
  v: 1,                    // 协议版本，见第 10 节
  state: 'undecided',      // undecided | linked | declined
  askedCount: 0,           // 已自动询问过几次（用于"最多问 3 次"）
  lastAskAt: 0,            // 上次自动询问的时间戳（用于"间隔 ≥ 2 天"）
  linkedAt: 0,             // 关联建立时间
  lastSyncAt: 0,           // 上次真正收到回传数据的时间
  lastWords: 0,            // 上次回传的词数（展示用）
}
```

**为什么要 `lastSyncAt` 单独记**：设置页要能回答"关联了到底有没有在同步"。
用户看不到数据流，如果只有"已关联"三个字，链接坏了也发现不了。所以展示"上次同步：今天 21:40 / 从未同步过"。

## 5. 触发时机

### 5.1 自动询问（唯一会自动弹窗的场景）

同时满足才弹，**缺一条都不弹**：

| 条件 | 说明 |
|---|---|
| ① 本 App 是 App 端 | H5 / 小程序没有"检测已安装应用"这回事，直接跳过 |
| ② 检测到伙伴 App 已安装 | `plus.runtime.isApplicationExist` |
| ③ `state === 'undecided'` | 关联过 / 明确拒绝过都不再问 |
| ④ `askedCount < 3` | 最多主动问 3 次 |
| ⑤ 距 `lastAskAt` ≥ 2 天 | 不连续两天骚扰 |
| ⑥ 当前不在专注中 | **番茄跑着的时候绝不弹窗**——这是硬规矩 |
| ⑦ 本次启动还没弹过 | 冷启动 1.2s 后检查一次，之后不再重试 |

### 5.2 不弹的场景（同样重要）

- 用户正在专注（⑥）—— 改到回到首页且没有进行中的番茄时再补一次检查
- 用户已在设置页主动处理过 —— 状态不再是 undecided
- 伙伴 App 未安装 —— 设置页显示"未检测到"，不弹窗也不灰心，装了再来

### 5.3 手动入口（永远可用）

设置页 → 「关联背单词 App」，任何时候都能改，与自动询问完全解耦。

## 6. 弹窗文案与选项

### 6.1 首次询问

**标题**：`发现「AWword」`

**正文**：

```
检测到你手机上也装了 AWword（背单词 · 翻译练习）。

关联之后：
· 从 PWstudy 的计划里点一下，直接进 AWword 学
· 学完带回来：学了多久、学会了几个词，自动记进今天

不关联也完全不影响使用 —— 你照旧可以用别的背单词 App，
PWstudy 一样记得住你的专注时间。
```

**三个按钮**：

| 按钮 | 行为 | 后续 |
|---|---|---|
| `关联` | `state = 'linked'`，记 `linkedAt` | 不再自动弹；学习 App 入口里出现 AWword |
| `以后再说` | `askedCount + 1`，记 `lastAskAt` | 满足 5.1 条件时最多再问 2 次 |
| `不用了` | `state = 'declined'` | **永不再自动弹**；设置页仍能重新关联 |

**为什么必须给「不用了」而不是只有「以后再说」**：
一直"以后再说"、一直弹，本质就是软绑架。用户要能一句话永久关掉这件事。

### 6.2 关联成功

`已关联。从首页的学习 App 里点 AWword 就能直接过去。`

### 6.3 取消关联（二次确认）

**标题**：`取消关联？`

**正文**：
```
取消后 PWstudy 不再跳转到 AWword，也不会再弹这个提示。

已经记进今天统计的学习数据会保留（那是真实发生过的），
不会因为你取消而被抹掉。随时可以在这里重新关联。
```

按钮：`取消关联` / `再想想`

## 7. 设置页入口：完整流程

### 7.1 四种展示形态

| 状态 | 标题行 | 副文案 | 操作 |
|---|---|---|---|
| 未安装 | 关联背单词 App | 未检测到 AWword。装了之后可以在这里关联 | 无（按钮置灰/隐藏） |
| 未决定 | 关联背单词 App | 装好了，关联一下？ | `关联` |
| 已关联 | 关联背单词 App · 已关联 | 上次同步：今天 21:40 · 30 词 | `取消关联` |
| 已关闭 | 关联背单词 App · 已关闭 | 你之前选择不关联 | `重新关联` |

### 7.2 操作流程

```
进入设置 → 找到「关联背单词 App」
   │
   ├─ 未安装：只读说明，不给按钮（不给按钮 = 不给用户制造"我该点什么"的困惑）
   │
   ├─ 未决定：点「关联」→ 写 state=linked → toast「已关联」
   │
   ├─ 已关联：点「取消关联」→ 二次确认（6.3）→ 写 state=declined
   │            → toast「已取消关联，已记录的数据保留」
   │
   └─ 已关闭：点「重新关联」→ 写 state=linked → toast「已重新关联」
```

### 7.3 一个容易漏的点

**从「已关联」取消后，状态落到 `declined` 而不是回到 `undecided`。**
否则下次启动又会重新弹那个首次提示——用户刚明确取消，转头又被问一遍，是最招人烦的一种设计。

## 8. 同步的数据 / 状态范围

### 8.1 通道

只有一条：`URL scheme` 跳转时携带参数（第 3 节已说明原因）。

### 8.2 当前已落地（v1）

**PWstudy → AWword**（`awword://study`）

| 字段 | 含义 |
|---|---|
| `minutes` | 建议时长（来自当前任务/番茄配置） |
| `task` | PWstudy 的任务 id，学完带回来才能对上号 |
| `back` | 回跳地址（urlencode 过的 `pwstudy://vocab-done?...`） |

**AWword → PWstudy**（`pwstudy://vocab-done`）

| 字段 | 含义 | 落点 |
|---|---|---|
| `min` | **真实**停留分钟 | `daily[date].byApp['app:awword']` |
| `words` | 本次确认通过（真学会）的词数 | `daily[date].vocabWords` |
| `task` | 任务 id | 便于将来回写任务进度 |

两点硬性约定（已在代码中钉住）：
- `min` 必须是真实时长，**不许把对方给的"建议时长"原样还回来**，否则统计全是假的
- `words` 用"确认通过 = 真学会"，不是"做过几道题"

### 8.3 建议扩展（v1.1，需 AWword 侧配合）

| 字段 | 方向 | 用途 | 备注 |
|---|---|---|---|
| `todayWords` | A→P | 今日累计背词 | 比"本次"更有意义，能在首页直接显示 |
| `book` | A→P | 当前词书名 | 展示用，让人知道这 30 分钟花在哪本书上 |
| `streak` | A→P | 连续天数 | 可喂成就感/教练话术 |
| `doneToday` | A→P | 今天是否已背 | 可喂打卡 |
| **`due`** | **A→P** | **复习队列积压数** | **最有价值的一项**：能进 PWstudy 的紧迫度卡——"你那边还有 40 个词等着复习"是真实的紧迫感来源 |
| `goal` | P→A | 目标标题 | 让 AWword 那边知道这次是为哪个目标在学 |

**`due` 为什么值得单独提**：PWstudy 的紧迫度卡现在只能算"任务还剩多少番茄"，
看不到"背单词那边积压了多少复习"。而复习积压恰恰是最容易被拖延、也最该被提醒的东西。
这是两个 App 联动之后**唯一能产生 1+1>2 效果**的数据点。

### 8.4 明确不同步的（写清楚同样是设计）

| 数据 | 不同步的原因 |
|---|---|
| 词书内容 / 词条 / 掌握度 | URL 塞不下，且属于 AWword 的核心资产，不该外流 |
| 错题本 | 同上 |
| 历史曲线 / 热力图 | 同上，且两边各自画自己的更清楚 |
| 账号 / 任何标识 | 两个 App 都没有账号体系，也不该为此引入 |

## 9. 取消关联后的处理

### 9.1 立即停止

- 不再自动弹任何提示
- 首页「学习 App」里不再出现 AWword 直达入口
- 不再发起跳转（`openPartner` 直接返回 false）
- 设置页显示「已关闭」+ `重新关联`

### 9.2 数据保留（关键决策）

**已经记进 `daily[]` 的时长和词数，一律保留，不回滚。**

理由：那是真实发生过的学习，不是"因为关联才产生的数据"。
因为取消关联就把今天的 25 分钟抹掉，等于惩罚用户做了一个正常的选择。
设置页的二次确认里也明确写了这一点（6.3）。

### 9.3 对方侧感知

跳转时带 `linked=1`，对方据此决定是否显示来路横幅。
取消关联后不再跳过去，对方自然就没有来路横幅——**不需要额外发一条"我取消了"的通知**，
那会给纯本地应用平白增加一个失败通道（跳过去的时候用户可能根本没开 AWword）。

### 9.4 恢复

设置页点「重新关联」即可，不需要重新授权、不需要重新登录（本来就没有）。
`lastSyncAt` 保留，所以恢复后能看到"上次同步是 X 天前"。

## 10. 协议与可扩展设计

### 10.1 版本号

跳转参数带 `v=1`。收到不认识的版本：
**不报错、按 v1 处理**（双方都还在快速迭代，版本号应该用来"知道对方更旧"，而不是"拒绝服务"）。

### 10.2 字段规则（沿用已有约定）

- 字段名一律小写，时间统一**分钟**，id 用各自 App 自己的
- **任何一端加字段都只能加可选的** —— 老版本忽略未知字段，绝不能因为多一个字段就整条链接判死
- 未知字段一律忽略，不做校验

### 10.3 伙伴注册表（为将来留口子）

现在只有 AWword，但代码里按"注册表"组织，将来接入别的背单词/学习 App 时只需要加一项：

```js
const PARTNERS = {
  awword: {
    id: 'awword',
    name: 'AWword',
    pkg: 'com.AWword',        // Android 包名（检测安装 + UsageStats 归类）
    scheme: 'awword',         // 自己的 scheme
    key: 'app:awword',        // 在 PWstudy 统计里的归属 key
    minVersion: 1             // 期望的最低协议版本
  }
}
```

用户提到"PWstudy 并非背单词的唯一选项"——所以这个注册表是**给第三方 App 留的**，
AWword 只是第一个接入的，不该享受任何特殊硬编码待遇。

### 10.4 与「学习 App（dock）」的关系

两者是**并列**的，不是替代：

- `dock` 里登记的是**任意**学习 App（第三方也算），PWstudy 用 UsageStats 统计它们的用时
- `partner` 是**愿意配合跳转并回传细节**的那个 App

一个 App 可以同时是 dock 里的学习 App、又是伙伴 App。
统计口径保持一致：伙伴 App 回传的时长进 `byApp['app:awword']`，
与 dock 里其它 App 走同一张表，这样"今日学习 App 用时"那张卡才不会出现两套数字。

## 11. AWword 侧需要改造的点（交接清单）

> **必须**（不做则整套联动不成立）：11.1 / 11.2 / 11.3 / 11.6 / 11.7 / 11.8
> **增强**：11.4 / 11.5
>
> 11.6–11.8 是"两边都要能问、都要能关"这一条需求带来的，属于同一次交付。

### 11.1 【必须】包名固定并告知

PWstudy 需要用包名检测 AWword 是否已安装。**2026-10-12 已确认固定为 `com.AWword`**（从 AWword 的 debug APK 清单读出），
一旦发布就不要再改——包名变了，老用户的关联状态全部失效。

### 11.2 【必须】声明 `<queries>`（若 `targetSdk >= 30`）

Android 11+ 起包可见性受限：`targetSdk >= 30` 的应用默认**看不到**其它已安装应用，
必须在 manifest 里声明才能检测到 PWstudy：

```xml
<queries>
  <package android:name="com.PWstudy" />
</queries>
```

（PWstudy 侧 `targetSdk = 28`，不受此限制，但建议也补上，以免将来升级时踩坑。）

### 11.3 【必须】保持 scheme 与协议字段

已完成的：`schemes: ["awword"]`、`awword://study?minutes=&task=&back=`、
回跳 `pwstudy://vocab-done?min=&words=&task=`。
**字段改名请提前说**——两端是分别发布的，改名会造成"新 PWstudy + 旧 AWword"期间静默失效。

### 11.4 【建议】回跳时补扩展字段

在 8.3 那张表里，最值得先加的是 **`due`（复习积压数）**。
它会被 PWstudy 的紧迫度卡用上——这是联动唯一能产生额外价值的数据点。其余字段按优先级排。

### 11.5 【建议】同步入口 `awword://sync`

目前只有"从 PWstudy 跳过来学"这一个数据流。建议 AWword 也提供一个反向入口：
用户在 AWword 学完一批后点「同步到 PWstudy」，跳一次把 `todayWords / streak / due` 带过去。
**必须是用户主动触发**，不要在 AWword 里自动跳到 PWstudy——那会把人从学习状态里拽出来。

### 11.6 【必须】对称的首次询问（这条是需求原文要求的）

需求写的是"安装并打开**其中任一 App**"时都要问，所以 AWword 侧也要有同一套：

- 启动时（首页 `onShow`）用 `plus.runtime.isApplicationExist({ pname: 'com.PWstudy' })`
  检测 PWstudy 是否已安装
- 条件与本设计 5.1 完全一致：装了 + 未决定 + 没问够 3 次 + 距上次 ≥ 2 天 + **不在练习中**
- 三选一弹窗：打通（推荐）/ 以后再说 / 不用了，落点与 6.1 一致
  （「不用了」落到 `declined`，**不退回 undecided**）
- 状态存 AWword 自己的设置项，字段与本设计第 4 节同名同义即可，**不需要两边同步**

⚠️ **两边各自的意愿各自存**，不要设计成"双方都同意才生效"——
那样任何一侧卸载重装、清数据，另一侧就会变成谁也解不开的死结。

### 11.7 【必须】对称的设置入口

AWword 设置页放一栏「关联 PWstudy」，四态（未安装 / 未决定 / 已关联 / 已关闭）+ 四个动作
（关联 / 取消关联 / 重新关联 / 重新检测），与本设计第 7 节一致。
**取消关联同样只断跳转与回传，不删任何学习记录。**

### 11.8 【必须】已关闭时怎么对待 `back`

跳转参数里 PWstudy 会带 `linked=0/1`。建议规则：

| linked | AWword 的行为 |
| --- | --- |
| `1` | 顶部显示来路横幅「从 PWstudy 过来」，学完**自动**带 `min`/`words` 回跳 |
| `0` | 顶部横幅降级为一行提示 + 一个「回去」按钮，**不自动跳**（用户点了才回） |
| 无此参数 | 按 `1` 处理（兼容旧版 PWstudy） |

`linked=0` 时**仍然要让回得去**——用户是点了 PWstudy 里的入口才过来的，
学完回不去跟绑架没区别。区别只在于"自动"还是"手动"。

### 11.9 一条通用约定

**任一侧不知道对方的新版本时，按旧版本处理，绝不报错、绝不静默丢弃整条链接。**
两个 App 都在快速迭代，这是保证"新旧混装"期间可用性的前提。
