# 任务完成反馈 + 每日任务动态重排

> 代码位置：数据层 `utils/pwstore.js`（完成台账 / 重排状态）、编排层 `utils/harvest.js`、
> AI 层 `services/plan-agent.js`、UI `components/task-done-dialog` + `pkgPlan/pages/harvest/harvest`。
> 护栏：`_tools/check-harvest.js`（真跑 160 条断言）+ `_tools/_scratch/neg-harvest.js`（30 条反向测试）。

这条链路回答四件事：

1. 完成一项任务 → 弹「恭喜你完成任务」，可去记一句**额外收获**；
2. 今天的完成情况（做了什么、几点做完的、本人怎么说）**完整存本地**；
3. 今天全做完 → **自动**综合当天 + 历史反馈重排后续，不用用户确认；
4. 过了 00:00 昨天还有没做完的 → 同样**自动**重排；数据不够判断时先问本人一句再排。

## 一、本地数据结构

### 1.1 完成台账：`daily[date].done`

挂在"每天"上（和 `focusMin` / `byApp` / `log` 同级），不是另开一个 store ——
跟学习进度同生共死：清数据一起清、备份一起走。

```
fj_pw_data_v1
└─ daily
   └─ '2026-10-14'
      ├─ focusMin / pomo / byApp / byHour   ← 原有，不动
      ├─ log                                 ← 收工填报（dailylog.js），不动
      └─ done                                ← 本功能新增
         ├─ updatedAt: 1791920812291
         └─ items: [
              {
                goalId:   'm3k9x',            // 所属目标
                taskId:   't7b2q',            // 所属任务
                title:    '背单词',            // 任务内容（快照，任务改名不影响历史）
                goalTitle:'考研英语',
                day:      1,                   // 计划里的第几天
                pomos:    2,                   // 计划的专注数
                at:       1791920812291,       // 完成时刻（毫秒）
                atText:   '09:42',             // 完成时刻（人看的 HH:MM）
                src:      'manual',            // manual 手工勾 / pomo 专注跑满 / log 收工填报 / chat 对话记功
                harvest:  null                 // 额外收获（见下），没填是 null
              }
            ]
```

**同一天同一任务只留一条，且保留首次完成时间**（勾了又取消又勾上，不堆两份、
"几点做完的"也不被最后一次覆盖）。两道锁：`markTaskDone` 的 `first` 判断 +
`ledgerAdd` 的去重 —— 任一单着就够挡住。

### 1.2 额外收获：`items[].harvest`

```
harvest: {
  at:     1791921455000,   // 填表的时刻
  atText: '09:50',
  date:   '2026-10-14',
  raw:    '今天状态好\n阅读比想象中快',   // 原话（多轮累积，换行分隔）
  summary:'10-14 09:42 完成「背单词」，阅读速度比预估快，后面可以加量', // AI 总结（40 字内）
  tags:   ['速度', '阅读'],               // 最多 3 个
  src:    'ai'                            // ai = 模型总结；local = 原话直存
}
```

AI 不可用（没配 / 关了分项开关 / 断网 / 模型抽风）时 `src='local'`，
`summary` 退化为 `date + ' ' + atText + ' 完成「title」，本人补充：' + 原话截 60 字` ——
**原话绝不丢**，而且照样带日期时间，回看时不会只剩一句没头没尾的话。

### 1.3 重排状态：`st.replan`

只存"跑到哪一步了"和"上次的结果"，判断逻辑全在 `harvest.js`。

```
replan: {
  lastSweepDate: '2026-10-14',                    // 上次跑「跨天兜底重排」的日期（一天一次）
  lastAllDone:   { date: '2026-10-14', at: 1791920812291 },  // 上次跑「全部完成重排」
  last: {                                          // 最近一次结果（下次要读它，防来回横跳）
    at: 1791920812291, kind: 'alldone',            // alldone | sweep
    goalId: 'm3k9x', applied: 2, src: 'ai',        // ai | ai-empty | ai-error | local
    summary: '你连着两天没做完，后面的量往下压一档',
    detail:  '「做阅读」改成 1 段专注'
  },
  pending: [                                       // 不敢自动落地的"大动作"，等人点头
    { op:'drop',  goalId:'m3k9x', taskId:'t7b2q', title:'做阅读', reason:'太难了', at:… },
    { op:'defer', goalId:'m3k9x', days:5, title:'考研英语', reason:'来不及', at:… }
  ],
  lastNote: '每天最多 2 段专注'                     // 信息不足时问来的最新意见
}
```

## 二、触发时机

| # | 触发 | 入口 | 是否要用户确认 |
|---|------|------|----------------|
| 1 | 完成任意一项任务 | `schedule-list` 抛 `done` → 首页 / 日历页弹窗 | 弹窗本身（取消 / 额外收获） |
| 2 | 点「额外收获」 | 跳 `pkgPlan/pages/harvest/harvest` | 自由输入，可跳过 |
| 3 | 当天任务**全部完成** | 首页 `onShow` → `harvest.autoReplan()` | **不用**，自动 |
| 4 | 过了 00:00 昨天还有没做完的 | 首页 / 日历页 `onShow` → `harvest.sweep()` | **不用**，自动 |
| 5 | 数据不够判断 | 上面 3/4 之前 `needsAsk()` | **要**，问一句再排 |
| 6 | 自动重排里出现砍任务 / 顺延期限 | `pending` 队列，进首页时问一次 | **要** |

### 2.1 三条完成路径必须收敛到同一个出口

```
手工勾完成   setTaskStatus(id, 'done')  ┐
专注跑满     addPomoToTask()            ├→ markTaskDone(g, t, src) → status='done' + 记台账
收工/对话补记 creditPomo()               ┘
```

**任何一条漏掉，都会出现"任务显示已完成但台账没有"** —— 于是"今天全部完成"永远判不出来、
自动重排永远不触发。这是整套功能最脆的一环，所以：
`pwstore.js` 里 `status = 'done'` 只允许出现一次（在 `markTaskDone` 里），
三个入口都必须调它。护栏静态守这条。

### 2.2 弹窗与返回键

`components/task-done-dialog` 复用 `app-dialog`（页面不许自己写弹窗）。
点「取消」或**系统返回键**都关弹窗回原页面 —— 两个挂载页面（首页 / 日历页）
的 `onBackPress` 第一行都要先收弹窗。

## 三、判断逻辑与边界条件

### 3.1 「今天全部完成」四个条件缺一不可

```js
allDoneOn(date) =
    今天确实有安排（rowsOf(今天) 非空）        // 今天本来就没任务，谈不上"全做完"
 && 今天的安排里没有 todo（done / dropped 都算了结）
 && 没有历史欠账（todayQueue 里 overdue 为 0）  // 有欠账走"跨天兜底"那条线，两条线不重合
 && 今天至少真完成了一项（台账非空）            // 否则"所有任务都是以前勾完的"这种
                                              //   静止状态每天都被判全做完 → 天天重排
```

### 3.2 「跨天兜底」的边界

* 最多**回溯 3 天**：用户一周没开 App，不该在打开那一刻连补 7 次重排。
* 那天没安排就跳过（`continue`），找到第一个**有安排且有 todo** 的日子为止。
* **首次启动不跑**：没有 `lastSweepDate` 就只记日期、不重排 —— 刚装 App 的人
  没有"昨天"，凭空重排一份还没开始执行的计划没有意义。

### 3.3 一天最多自动重排一次

全部完成那条线记 `lastAllDone.date`，兜底那条线记 `lastSweepDate`。
否则勾一个任务跑一次模型，一晚上能烧掉几十次调用。设置页手动触发用 `force: true` 绕过。

### 3.4 自动只落地"可逆的日常调整"

| op | 含义 | 自动 | 确认后 |
|----|------|------|--------|
| `move` | 改期 | ✅ | ✅ |
| `resize` | 改量 | ✅ | ✅ |
| `note` | 建议文字（不落库） | — | — |
| `drop` | 砍任务 | ❌ → 进 pending | ✅ |
| `defer` | 顺延截止日 | ❌ → 进 pending | ✅ |

**用户要的是"别再来烦我确认"，不是"你可以悄悄把我的任务删了"。**
砍掉的任务事后想反悔很难，一律进 `pending` 单独问一次（最多 8 条）。
被"先不动"驳回的**必须出队**，否则每次进首页都弹同一条。

数值夹取：`move.day ∈ [1, 期限内]`、`resize.pomos ∈ [1, 20]`、`defer` 单次与累计都封顶 90 天
（再多就不是"调整计划"而是"换个目标"）。

### 3.5 AI 不可用必须照样重排

`localRoll()`：把"今天及以后还没做的"按剩余天数重新铺开，
`cap = ceil(剩余总专注 / 剩余天数)`，**原顺序与相对先后一律保留**
（本地规则不负责判断哪件事更重要，那是模型的事）。

三种情况都走它，且给用户的说法要分开：

| 情况 | `src` | 文案 |
|------|-------|------|
| 没配 AI / 关了开关 | `local` | 没用 AI，按剩余天数把剩下的任务重新铺了一遍。 |
| 连不上 / 模型报错 | `ai-error` | 这次没连上 AI，先按剩余天数… |
| 跑通了但一条建议都没给 | `ai-empty` | AI 这次没给出调整，已按剩余天数… |

⚠️ 后两种**不能说成一样** —— 把故障说成"它觉得不用改"等于瞒报。

### 3.6 信息不足的三条判据（都是本地算的，不用问模型）

| why | 判据 | 问什么 |
|-----|------|--------|
| `completed-pomo-lt-3` | 完成的专注 < 3，没有速度基线 | 这次想怎么安排？（比如"每天最多 2 段专注"） |
| `no-focus-in-7d` | 近 7 天 0 分钟，连真实投入都没有 | 最近的学习时间大概什么样？ |
| `short-without-reason` | 连续没做完，却既没收工填报也没额外收获 | 方便说一句卡在哪吗？ |

命中且**还没有本人意见**时：不硬排，把问题抛给调用方去弹窗；
问来的话存 `lastNote`，下次重排作为**最高优先级**上下文喂给模型。
空意见不覆盖旧意见（手滑清空不会丢）。

## 四、闭环

```
      完成任务 ──弹窗──→ 额外收获（原话）
                            │
                            ↓  AI 总结（带日期时间）
      完成台账 daily[date].done.items[].harvest
                            │
                            ↓  historyBlock / summaryFor
   全部完成 or 跨天兜底 → 拼 extra ──┐
                                     │
              本人最新意见 lastNote ──┤
              上次重排结果 lastBlock ─┘   ← 要求"别重复已做的调整、别来回横跳"
                            │
                            ↓  模型
                     ops（move/resize/drop/defer/note）
                            │
              ┌─────────────┴─────────────┐
              ↓                           ↓
   可逆动作：直接落地              drop / defer：进 pending 问一次
              │                           │
              └───────────┬───────────────┘
                          ↓
              记 replan.last（判断 + 落地了什么）
                          ↓
                  下次重排读它（闭环）
```

`lastNote` 不消费完就消失 —— 一直有效到被新的覆盖。
`pending` 与 `last` 都存 storage（自检一天一次，放内存会闪一下就没）。

## 六、容易改坏的地方（护栏在守）

1. 完成路径多一个直接改 `status='done'` 的地方 → 台账漏记 → 自动重排永不触发。
2. `allDoneOn` 少一个条件 → 静止状态天天重排 / 欠账被排两次。
3. `AUTO_OPS` 里加 `drop` / `defer` → "不用确认"变成"悄悄删我任务"。
4. `pending` 只回给调用方、不落队列 → 每次进首页重复问同一条。
5. AI 报错和 AI 没给建议说成同一句话 → 瞒报故障。
6. 反向测试里"不堆第二条"有双锁，只拆一把不会红 —— 必须两把一起拆。
